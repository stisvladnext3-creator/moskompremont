# Обновление кабинета: подписки, обращения и уведомления

В этом обновлении:
- у клиента может быть несколько подписок; названия при регистрации вводятся через пробел, запятую, точку с запятой или с новой строки;
- существующие свободные подписки привязываются сразу по названию, без дополнительного подтверждения — как выбрано владельцем сайта;
- уведомления о новых клиентах, оплатах и сообщениях сохраняются в админке и ставятся в очередь писем на sania.iwannikow@yandex.ru;
- разделы администратора: «Обращения», «Новые пользователи», «Оплаты», «База подписок», «Почта»;
- администратор отвечает на обращения в кабинете; клиент видит ответы в своей переписке;
- после проверки оплаты администратор вручную выдаёт одну или несколько подписок;
- исправлен минимальный размер данных перевода: 4 символа, например 3015.

## Установка поверх работающего сайта

1. Сохраните резервную копию базы и файлов сайта. Сохраните свой `private/config.php`, `assets/config.js` и банковский QR. В архиве обновления этих файлов нет; заменять их не нужно.
2. В phpMyAdmin выберите существующую базу сайта → «Импорт» → выберите `private/migrations/002-cabinet.sql` из архива → выполните импорт под учётной записью с правом CREATE. Добавятся только новые таблицы. Текущие пользователи, пароли, заявки и оплаты не удаляются. Повторное выполнение этого файла не очищает данные.
3. Загрузите файлы архива обновления в папку сайта, сохраняя структуру. `account.html`, `assets/account.js`, `assets/account.css`, `api/account.php` обновляются; добавляются серверные PHP-файлы и библиотека PHPMailer в private. Не переносите PHP-файлы в папку assets.
4. Откройте существующий `private/config.php`. Сохраните настройки БД, origin, QR, получателя и admin_user_ids. Добавьте перед закрывающим `];` новые параметры из примера ниже. Не создавайте второй `return` и не удаляйте существующие параметры.
5. Найдите в internet_users ID аккаунта sania.iwannikow@yandex.ru. Убедитесь, что это ваша запись. Этот ID должен быть в `admin_user_ids`. Например, если ID — 7: `'admin_user_ids' => [7],`. Адрес уведомлений сам по себе не выдаёт административные права.
6. Обновите account.html через Ctrl+F5. Для админа откроется панель с отдельными разделами. Для клиента — подписки, оплаты и поддержка.
7. После импорта удалите публичные копии schema.sql и папку private/migrations с сервера либо убедитесь, что вся private закрыта для HTTP. SQL-файлы сохраняйте у себя для резервной копии.

## Почта: настройка Яндекса

Отправка требует настройки на ВАШЕМ хостинге. В архиве нет почтовых паролей; до настройки письма сохраняются в очереди. Уведомления в админке работают независимо от почты.

В настройках Яндекс.Почты разрешите доступ почтовым программам, если он отключён. В Яндекс ID создайте отдельный пароль приложения для Почты. Это не пароль от кабинета сайта и не пароль пользователя MySQL. Впишите его только в конфигурацию на сервере либо в переменную окружения INTERNET_SMTP_PASSWORD.

В существующий PHP-массив config.php добавьте:

```php
'admin_email' => 'sania.iwannikow@yandex.ru',
'app_path' => '', // если account.html находится в подпапке, укажите её, например internet
'mail' => [
    'enabled' => true,
    'transport' => 'smtp',
    'from' => 'sania.iwannikow@yandex.ru',
    'from_name' => 'МосКомпРемонт',
    'smtp_host' => 'smtp.yandex.ru',
    'smtp_port' => 465,
    'smtp_encryption' => 'ssl',
    'smtp_auth' => true,
    'smtp_user' => 'sania.iwannikow@yandex.ru',
    'smtp_password' => 'СЮДА_ПАРОЛЬ_ПРИЛОЖЕНИЯ_ПОЧТЫ',
],
```

Весь конфигурационный файл должен оставаться внутри `<?php return [ ... ];`, как раньше. У параметра, который стоит перед новым блоком, должна быть запятая.

Хостинг должен разрешать исходящие соединения с smtp.yandex.ru:465 и иметь PHP OpenSSL с актуальными корневыми сертификатами. Если соединение блокируется, обратитесь в поддержку хостинга. Не отключайте проверку сертификатов.

Зайдите в админке в «Почта» → «Отправить тестовое письмо». Затем обновите статус. «Принято почтовым сервером» означает, что SMTP принял письмо; проверьте также входящие и спам в Яндекс.Почте.

Если ваш хостинг уже умеет отправлять PHP mail(), можно использовать `'transport' => 'mail'`, указав в `from` разрешённый почтовый адрес вашего домена. Для отправки от адреса @yandex.ru используйте SMTP Яндекса, а не подмену From через PHP mail.

## Повторная отправка и cron

При регистрации/оплате/сообщении сервер сразу сохраняет уведомление и письмо в базе. Затем пытается отправить одно письмо. Ошибка SMTP не отменяет регистрацию, оплату или обращение.

Чтобы очередь отправлялась без посещений сайта и восстанавливалась после временного сбоя, добавьте в панели хостинга задание cron раз в 5 минут:

```text
*/5 * * * * /usr/bin/php /ПОЛНЫЙ/ПУТЬ/К/САЙТУ/private/send-mail.php
```

Выберите версию PHP CLI 8.1+ с pdo_mysql и openssl. Точный путь к PHP и папке сайта указан в панели/у поддержки хостинга. Если config.php вынесен за пределы сайта, задайте INTERNET_CONFIG и для cron, например:

```text
*/5 * * * * INTERNET_CONFIG=/home/USER/private/internet-config.php /usr/bin/php /home/USER/public_html/private/send-mail.php
```

Скрипт обрабатывает до 10 писем за запуск, повторяет неудачные отправки с паузами, после 10 попыток показывает ошибку. После исправления SMTP нажмите в админке «Повторить отправку очереди». Обращаться к send-mail.php через браузер не нужно: он работает только из CLI.

## Загрузка базы подписок

Источник истины — MySQL. Файл CSV нужен только для удобного импорта, публичного файла со всеми ссылками на сайте нет.

1. Откройте шаблон `private/subscriptions-template.csv` на компьютере. Первая строка: `name,url`.
2. Заполните строки вашими реальными названиями и ссылками. Пример формата, который нужно заменить своими данными:

```csv
name,url
VPN5089,https://example.com/ВАША_ССЫЛКА_1
VPN5090,https://example.com/ВАША_ССЫЛКА_2
```

3. Сохраните CSV в UTF-8. Допускается разделитель запятая или точка с запятой. Если в ссылке есть запятая, CSV должен обрамлять такую ячейку кавычками — табличный редактор делает это при сохранении.
4. Админка → «База подписок» → выберите CSV → «Загрузить в MySQL». За раз — до 1000 подписок и 1 МБ.

Названия — латинские буквы, цифры, точка, дефис или подчёркивание, до 100 символов. Регистр не важен: vpn5089 и VPN5089 считаются одним названием. Одно название соответствует одной ссылке. Если у клиента несколько ссылок — каждой задайте отдельное название.

Повторный импорт обновляет ссылку по названию и сохраняет назначенного владельца. Весь CSV проверяется до внесения изменений: при ошибке в строке частичный импорт не выполняется.

При регистрации клиент отмечает «У меня уже есть подписки» и пишет, например `VPN5089, VPN5090 VPN5091`. В его кабинете появятся все найденные свободные подписки. До 20 названий при регистрации; дополнительные можно указать после входа.

Если клиент зарегистрировался до загрузки базы, его запрос сохраняется. После импорта подходящая подписка привяжется автоматически, если на неё есть один ожидающий запрос. Если на одно название претендуют несколько клиентов, оно останется на ваше решение в «Запросах на подписки». Подписка, уже закреплённая за другим аккаунтом, повторно не выдаётся. Режим выдачи по одному названию выбран владельцем сайта и не подтверждает личность владельца подписки.

## Оплата и выдача

Клиент нажимает «Я оплатил» → в «Оплатах» появляется уведомление с клиентом, суммой, тарифом, устройствами и данными перевода → письмо ставится в очередь. Этот шаг не подтверждает поступление денег.

1. Проверьте поступление в Озон Банке.
2. В админке → «Оплаты» → нужная заявка → «Подтвердить поступление».
3. В той же заявке откроется форма выдачи: введите название и подписочную ссылку → «Выдать подписку».
4. Чтобы выдать ссылку из загруженной базы, укажите её название, а поле ссылки оставьте пустым.
5. Чтобы добавить несколько ссылок к одной оплате, после первой нажмите «Выдать ещё одну подписку» и повторите. Все они появятся в кабинете клиента и в его заявке.

До подтверждения оплаты сервер выдачу блокирует. Повторная выдача той же подписки по той же заявке блокируется. Для следующей оплаченной заявки того же клиента можно использовать уже принадлежащее ему название. Привязка ссылки не продлевает услугу на VPN-сервере автоматически: настройку самой услуги выполняет владелец.

## Переписка и уведомления

Клиент → «Поддержка» → тема и сообщение → «Отправить обращение». Администратор видит обращение и контактные данные в «Обращениях», получает письмо и может ответить прямо там. Ответ отображается клиенту в том же диалоге. Вкладка поддержки показывает новые ответы, открытая переписка обновляется примерно раз в 20 секунд.

В «Новых пользователях» видны имя, фамилия, почта, Telegram, время регистрации, запрошенные и выданные подписки. Пароли и их хеши не отображаются и не отправляются в письмах. Существующие пользователи также остаются в списке; обновление не рассылает уведомления о старых регистрациях.

## Ограничения

Автоматическая проверка банковских платежей, создание VPN-подписок во внешней системе, восстановление пароля и подтверждение почты письмом в этот архив не входят. Для email-уведомлений нужна реальная настройка SMTP/почты хостинга; она не может быть выполнена в архиве без параметров вашего сервера.
