# Проверка версии 0.1.1

Проверено 23 ноября 2026.

## Исправление 0.1.1: jq без регулярных выражений

Ошибка 0.1.0 воспроизведена: правильный HTTPS-адрес отклонялся до запроса кода устройства, потому что `test()` требует Oniguruma. Для воспроизведения и проверки исправления из официального исходного архива jq **1.7.1** собрана настоящая версия с `./configure --without-oniguruma --disable-maintainer-mode --disable-docs`. Контрольный вызов `"probe"|test("probe")` воспроизводит сообщение `jq was compiled without ONIGURUMA regex library`.

SHA256 официального архива `jq-1.7.1.tar.gz`: `478c9ca129fd2e3443fe27314b455e211e0d8c60bc8ff7df703873deeee580c2`.

В 0.1.1 все проверки адреса, токена и SHA256 используют базовые операции jq. На сборке без Oniguruma прошли 16 групп агента, включая проверки некорректных адресов/кодов/ответов, состояние при испорченном сохранённом токене и ввод настоящего TTY с отключённым echo до показа приглашения. Тот же набор прошёл под BusyBox ash с настоящим Xray 26.11.9. Сквозная проверка PHP/MySQL + TLS/curl + native Xray тоже использовала BusyBox и jq без Oniguruma.

Настоящий Entware opkg в изолированном offline-root обновил опубликованный IPK **0.1.0 → 0.1.1**; настройки и резервная копия сохранились. Принудительные флаги не использовались. Малый архив исправления содержит только установщик, новый IPK, checksums и инструкцию; файлы кабинета и SQL в него не включены.

Ниже также сохранены исходные проверки первой версии. Преобразователь VLESS и серверная авторизация в 0.1.1 не менялись.

## Выполнено

- Изучены руководство Corvus-Malus/XKeen и исходники jameszeroX/XKeen, коммит `978d3a4b9a30b060f90b7ddec52232978023b723`: каталоги Xray, native restart, фоновый запуск без TTY, `XKEEN_FOREGROUND=1`, задания Entware cron. Код XKeen/Xray в пакет не включён.
- Функциональные проверки агента: автообновление, повтор без перезапуска, уведомления, байтовый откат JSONC, отклонение конфигурации, неудачный restart, параллельное ручное редактирование, неоднозначные outbound-блоки, совпадение UUID, отзыв кода, неверный JSONC, сохранение чужих cron-задач, восстановление незавершённой операции, неподдерживаемый ключ, блокировка одновременных проверок. После `unlink` перезапуск службы не восстанавливает cron-задачу.
- Агент проверен под dash и BusyBox **1.35.0 ash**, JSONC и файловые операции — также BusyBox awk/cp/mv и другими утилитами. jq и транзакции файлов реальные. HTTPS API, процесс Xray/XKeen и cron в этих 12 группах заменены изолированными тестовыми инструментами; часть групп дополнительно использует настоящий Xray для проверки конфигурации.
- Native Xray **1.8.24** и **26.11.9** приняли конфигурации, выданные PHP-преобразователем: TCP, gRPC, WebSocket, HTTPUpgrade, Reality. XHTTP принят 26.11.9; 1.8.24 отклоняет его, что требует ручного обновления Xray и не разрешает перезапись рабочего файла.
- Сквозная проверка с настоящими PHP **8.4**, MariaDB **11.4**, TLS и curl: регистрация клиента, назначение VLESS-ключа, код устройства, HTTP legacy API, формат Xray, массовая смена домена в админке, получение нового ключа, native Xray validation, сохранение `tag`/`sockopt`/соседних файлов, атомарная замена, вызов restart, отправка состояния в кабинет, повтор без перезапуска, HTTP 401 после отзыва без изменения файла. Наследуемые `XRAY_LOCATION_CONFDIR`/`XRAY_LOCATION_CONFIG` не попадают во временную проверку. **Сам restart XKeen и процессная проверка роутера в этом тесте имитируются**, поскольку физический роутер не подключён.
- PHP/MySQL: доступ только к назначенному ключу, чужой ID не меняет источник, в метаданных нет ключей/токенов, пароль и удаление/снятие привязки отзывают код, отключение кода, истечение/продление подписки для прежнего OpenWrt API, CSRF/роли кабинета, хеширование секрета, дедупликация уведомлений, двукратный импорт миграции. Запоздавший отчёт о предыдущем ключе получает 409 и не помечает новый ключ применённым.
- PHP-преобразователь: UUID/host/port, IPv6, Reality/gRPC, TCP/raw, WS, HTTPUpgrade, XHTTP, RFC3986-параметры, отклонение неизвестных/неоднозначных настроек, неверных JSON, переносов строк и небезопасного `allowInsecure`.
- Chromium/Playwright: клиент 390 px, администратор 1280 px; только свои VLESS-ключи в форме Keenetic, команда установки, однократный показ токена, отсутствие токена в localStorage/списках устройств, скрытие при выходе/смене вкладки, запоздавший ответ после перехода, отключение кода, общий список роутеров в админке. Прежние клиентская и администраторская формы OpenWrt тоже проверены. Горизонтального переполнения и ошибок JavaScript нет.
- IPK установлен и удалён настоящим статическим **Entware opkg**, сборка `80503d94e356476250adaf1f669ee955ec26de76` от 05.11.2025, в отдельном `--offline-root`. ## Границы проверки

Физического Keenetic, реальных MIPS/ARM-устройств и всех выпусков KeeneticOS в этой среде нет. Не подтверждаются реальные SSH-порты/пароли клиента, доступность его Entware feed, состояние USB-накопителя, поведение при отключении питания, производительность конкретной модели и прохождение VPN-трафика до удалённого сервера. Проверка конфигурации и наличия процесса не доказывает, что UUID разрешён сервером или сервер доступен.

Модели без Entware, Mihomo вместо Xray, нестандартный каталог конфигураций, непреобразуемый ключ и зависимости, отсутствующие в старом feed, требуют отдельной настройки. Перед массовой установкой нужна пробная установка на одном из реальных Keenetic клиента.

Публикация архива в GitHub не загружает его на действующий PHP-хостинг. Владельцу нужно выполнить `INSTALL-KEENETIC.md`; только после этого команда установки из кабинета начнёт скачивать пакет с сайта.

## Повторение

```sh
python3 keenetic-updater/tests/agent.py
MKR_XRAY=/path/to/xray python3 keenetic-updater/tests/agent.py
MKR_TEST_JQ=/path/to/jq-without-oniguruma python3 keenetic-updater/tests/agent.py
MKR_TEST_SHELL='/path/to/busybox ash' MKR_BUSYBOX=/path/to/busybox MKR_XRAY=/path/to/xray python3 keenetic-updater/tests/agent.py
MKR_ENTWARE_OPKG=/path/to/entware-opkg python3 keenetic-updater/tests/package.py
```

Для HTTP-проверки поднимите изолированный PHP/MySQL fixture через `openwrt-updater/tests/server.py` (PHP с pdo_mysql, образ можно собрать из `tests/Dockerfile.php` в той папке), запустите `openwrt-updater/tests/backend.py`, затем `keenetic-updater/tests/integration.py`. Браузерные проверки — `node openwrt-updater/tests/cabinet.cjs` и `node keenetic-updater/tests/cabinet.cjs`, требуется Playwright/Chromium. Fixture использует порт 4201 и только тестовую базу `internet_test`. После проверки выполните `python3 openwrt-updater/tests/server.py stop`.
