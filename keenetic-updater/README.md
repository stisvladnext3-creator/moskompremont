# МосКомпРемонт: автообновление XKeen на Keenetic

Пакет Entware `mkr-xkeen-updater` получает **один назначенный клиенту ключ VLESS** из личного кабинета. При изменении ключа он заменяет выбранный outbound Xray и перезапускает XKeen. Период — 5 минут. Бессрочные/другие ключи клиента и подписки не затрагиваются.

Исследованы [руководство Corvus-Malus/XKeen](https://github.com/Corvus-Malus/XKeen) и [сам XKeen](https://github.com/jameszeroX/XKeen), исходный коммит указан в `SOURCES.json`. В руководстве входящие подключения находятся в `03_inbounds.json`, а ключ — в **`04_outbounds.json`**. Поиск работает по содержимому `.outbounds`, поэтому файл может называться, например, `04_inbound.json`.

## Для пользователя

1. Администратор включает вкладку **Keenetic** и назначает ключ в «Ключи для роутера».
2. В кабинете откройте **Keenetic → Создать код подключения** для нужного ключа.
3. Вставьте показанную команду в SSH **Entware**, затем вставьте код по запросу установщика.
4. Дальше обновление ключа в админке доедет до роутера автоматически.

Подробные действия владельца сайта и клиента: [INSTALL-KEENETIC.md](INSTALL-KEENETIC.md).

## Совместимость

Пакет не содержит исполняемых файлов под конкретный процессор: `Architecture: all`, POSIX shell + jq/curl из Entware. Нужны **уже работающие Entware, XKeen и Xray**, папка `/opt/etc/xray/configs`, работающий cron, достаточно места на USB/Entware и доступ к HTTPS-сайту. IPv4/IPv6 адрес ключа, TCP/raw, gRPC, WebSocket, HTTPUpgrade, XHTTP и TLS/Reality преобразуются на сайте; окончательное решение о поддержке принимает установленный Xray при проверке конфигурации.

Это не обещание поддержки любой прошивки или модели Keenetic. Устройства без Entware, Mihomo вместо Xray, неподдерживаемые параметры ключей и нестандартные каталоги требуют отдельной настройки. При несовместимости пакет сообщает о ручной настройке и сохраняет текущий файл. Физические роутеры и все версии KeeneticOS в этой среде не испытывались. Точный перечень проверок — `VALIDATION.md`.

## Что меняется

При единственном VLESS-outbound он выбирается автоматически. При нескольких выбирается единственное совпадение UUID; при неоднозначности нужна явная команда `target`. Выбор закрепляется, чтобы смена UUID в новом ключе не переназначила чужое подключение.

В выбранном блоке меняются `protocol`, `settings`, `streamSettings`. `tag`, `sockopt` (включая метки XKeen), `mux`, `sendThrough`, `proxySettings` и соседние outbound-блоки сохраняются. Файлы с входящими подключениями, правила маршрутизации, политики Keenetic, firewall и DNS пакет не редактирует. JSONC с комментариями/завершающими запятыми читается, изменённый файл записывается как обычный JSON.

Перед записью Xray проверяет временную конфигурацию с исходящими подключениями. Она не поднимает порты и не загружает повторно большие geodata списки. Затем файл заменяется атомарно, запускается `XKEEN_FOREGROUND=1 xkeen -restart`, проверяются код завершения и процесс Xray. При неудаче возвращается побайтовая копия исходного файла и включается режим уведомлений. Журнал незавершённой операции позволяет восстановиться при следующем запуске после обрыва питания/процесса. Бэкап хранится вне каталога configs.

Проверка синтаксиса и процесса **не подтверждает доступность удалённого VPN-сервера, валидность UUID на сервере и прохождение всего трафика**. Отдельную серверную проверку доступности на сайте пакет не заменяет.

## Команды

```sh
mkr-xkeen status
mkr-xkeen check
mkr-xkeen mode notify
mkr-xkeen mode auto
mkr-xkeen retry
mkr-xkeen target /opt/etc/xray/configs/04_outbounds.json proxy
mkr-xkeen rollback
mkr-xkeen unlink
```

`retry` повторяет попытку после устранения ошибки Xray. `rollback` возвращает последний успешный бэкап и включает уведомления; если файл менялся вручную, откат отменяется. `unlink` удаляет локальный токен и только свою задачу cron, сохраняя рабочую конфигурацию XKeen. Чтобы отозвать доступ на сервере, нажмите «Отключить код» в кабинете. Удаление пакета: `opkg remove mkr-xkeen-updater`.

Локальные настройки: `/opt/etc/mkr-xkeen/config.json`; состояние, бэкап и последний полученный ключ: `/opt/var/lib/mkr-xkeen/`. Каталоги имеют права `700`, файлы с ключами — `600`. Команда `status` не выводит ключи и токены. Не публикуйте содержимое этих каталогов. Резервная копия намеренно остаётся после удаления пакета для ручного восстановления.

Код устройства даёт доступ только к одной записи клиента, действует год и отзывается при сбросе пароля, удалении аккаунта/ключа, снятии привязки или отключении кода. На сайте хранится хеш секрета. На роутере секрет передаётся curl через закрытый файл настроек, без аргументов процессов и cron. TLS проверяется, перенаправления API не выполняются.

## Сборка

```sh
python3 keenetic-updater/build.py --out /tmp/mkr-keenetic-build
python3 keenetic-updater/tests/agent.py
```

Результат: IPK, установщик с закреплённым SHA256 IPK, отдельный архив пакета и отдельное обновление сайта. Установка локального IPK через Entware не требует отключения проверок подписей или контрольных сумм. Доставка идёт с вашего HTTPS-сайта; установщик проверяет закреплённый SHA256. Это проверка целостности, а не собственный подписанный OPKG-репозиторий.
