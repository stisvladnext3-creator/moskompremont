# МосКомпРемонт · обновление ссылки в OpenWrt / Podkop

Пакет подключает роутер к **одной** подписке или одному ключу из личного кабинета. Раз в 15 минут он получает актуальное подключение; по умолчанию сам заменяет `proxy_string` выбранной секции Podkop. Пароль клиента на роутере не хранится.

[Скачать пакет 0.1.0](https://github.com/stisvladnext3-creator/moskompremont/releases/tag/moskom-openwrt-v0.1.0) · [Пошаговая установка](INSTALL-OPENWRT.md)

## Что входит

- `mkr-router-updater`: служба procd, проверка по HTTPS, отдельный код устройства, автоматическая замена / режим «только уведомлять», резервная копия и журнал отката.
- `luci-app-mkr-router`: меню **Сервисы → МосКомпРемонт**, настройка режима и секции, проверка сейчас, просмотр/копирование новой ссылки, ручное применение и отключение кода.
- Обновление PHP-кабинета v21: вкладка OpenWrt для клиента и администратора, создание/отключение кодов, время последнего обращения и результат применения. Уведомления об обновлении и необходимости ручного действия попадают в кабинет; Web Push использует существующую настройку сайта.

## Совместимость и выбор подключения

Пакеты не содержат машинного кода: IPK `Architecture: all` для opkg (OpenWrt 23.05/24.10), APK v3 `arch: noarch` для apk (OpenWrt 25.12). Поддерживается современный LuCI с JavaScript views. Для автоматической записи распознаются **Podkop 0.3.x, 0.4.x, 0.5.x и 0.6.x**, секции `mode=proxy`, `proxy_config_type=url`. Обычные прямые ключи VLESS / Trojan / Shadowsocks заменяются целиком. Podkop и прошивка роутера не обновляются этим пакетом.

Если в кабинете выдана HTTPS-подписка со списком URI (текст или base64/base64url), пакет находит в ней **текущее подключение** по протоколу, идентификатору, порту и названию. Домен/IP при сопоставлении может измениться. Список других серверов не подставляется в Podkop. Если совпадений нет, их несколько, сменился идентификатор/название/порт или используется иной формат подписки, новая ссылка и доступные URI показываются для ручной замены. Смена только домена/IP типового VLESS сохраняет автоматическое сопоставление.

При нескольких секциях надо явно выбрать секцию. Неизвестная версия Podkop, `outbound`, `urltest`, многострочный `proxy_string` с запасными подключениями и неподдерживаемый протокол требуют ручной настройки. Пакет сохраняет исходное подключение и показывает причину; кнопку «Применить» нельзя использовать для обхода этой проверки.

Перед записью проверяются локальные/несохранённые изменения UCI. После ручного изменения подключения нужно сверить секцию и снова сохранить настройки пакета — это явно разрешает дальнейшее обновление выбранного поля.

## Откат и границы проверки

Перед заменой сохраняются `/etc/mkr-router/podkop.backup`, `previous-value` и журнал операции (доступ только root). Если Podkop уже работает, пакет перезапускает его, проверяет синтаксис конфигурации через `sing-box check` и состояние службы. При ошибке возвращает **только изменённое поле**, сохраняя другие настройки. После прерванной записи журнал используется для восстановления при следующей проверке. При конфликте с последующим ручным изменением автоматическое восстановление останавливается.

Если Podkop выключен, записывается новая ссылка без включения службы. Проверка конфигурации/процесса **не гарантирует доступность удалённого VPN-сервера**. Мониторинг сервиса на сайте остаётся отдельной функцией. Для проверки через реальное подключение понадобится испытание на вашем роутере.

## Доступ к сайту

Код устройства разрешает только чтение одной выбранной записи и отправку результата её применения. Он не даёт доступ к другим подпискам, чатам, аккаунтам или административным действиям. В базе хранится хеш секрета; сам код показывается один раз. Запросы передают код в `X-MKR-Router-Token`, а не в URL. Заголовок не пересылается серверу подписки; перенаправления при проверке не выполняются.

Код действует год. Его можно отключить в кабинете или стереть кнопкой «Отключить» на роутере. Смена пароля, удаление аккаунта, снятие/передача привязки останавливают доступ. Истечение срока подписки приостанавливает выдачу ссылки; после продления та же привязка снова работает. Старая уже установленная конфигурация при сетевой ошибке/отключённом коде не стирается.

## Сборка и проверка

Нужны Linux x86_64, Python 3, Docker и доступ к официальным репозиториям пакетов. Сборка не использует пользовательские ключи или панель 3x-ui.

```sh
python3 openwrt-updater/tests/platforms.py --work /tmp/mkr-build-platforms
python3 openwrt-updater/build.py --version 0.1.0 --out /tmp/mkr-dist
python3 openwrt-updater/tests/install.py --dist /tmp/mkr-dist --version 0.1.0
python3 openwrt-updater/tests/router.py
```

Rootfs OpenWrt и статический `apk mkpkg` закреплены контрольными суммами. IPK собирается в формате OpenWrt (gzip tar с `debian-binary`, `control.tar.gz`, `data.tar.gz`), APK — настоящим `apk mkpkg` с владельцем root. Службы Podkop/sing-box и ответы сервера в функциональных тестах заменены управляемыми имитациями; UCI, BusyBox, opkg/apk и rpcd/ubus используются настоящие. Аппаратный роутер пока не предоставлен.

Также есть Makefile-пакеты для OpenWrt SDK в `package/`. Для SDK скопируйте **всю** папку `openwrt-updater` в `package/openwrt-updater`, затем выберите оба пакета через `make menuconfig` и выполните `make package/mkr-router-updater/compile V=s` и `make package/luci-app-mkr-router/compile V=s`.

Исходные схемы Podkop проверены по [v0.3.4](https://github.com/itdoginfo/podkop/tree/v0.3.4), [v0.4.11](https://github.com/itdoginfo/podkop/tree/v0.4.11), [v0.5.8](https://github.com/itdoginfo/podkop/tree/v0.5.8), [v0.6.1](https://github.com/itdoginfo/podkop/tree/v0.6.1). Формат APK: [документация OpenWrt](https://openwrt.org/docs/guide-user/additional-software/apk). Код пакета распространяется под GPL-2.0-or-later; см. LICENSE.
