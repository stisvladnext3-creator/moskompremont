# Мониторинг подписки и фоновая отправка писем — Ubuntu + PHP-хостинг

Страница: **https://moskompremont.ru/internet.html**. API 3x-ui не требуется. Служба использует отдельную копию уже установленного Xray, не редактирует настройки 3x-ui и не занимает публичные порты. Для Ubuntu нужен SSH с sudo/root, Python 3.8+, curl и работающий Xray из 3x-ui.

## 1. Обновить файлы и базу сайта

1. Сделайте резервную копию файлов сайта и базы.
2. Распакуйте `moskompremont-cabinet-v8-update.zip`. Загрузите содержимое в ту папку сайта, где лежат `account.html` и `internet.html`, с заменой одноимённых файлов.
3. При установленной v5/v6/v7 импортируйте **private/migrations/005-monitoring.sql** в существующую базу из `private/config.php`. Новая таблица самостоятельная, без внешних ключей и очистки данных.
4. Для версии до v5 или новой установки импортируйте полный **private/schema.sql** вместо отдельной миграции. Он создаёт недостающие таблицы в правильном порядке, сохраняя существующие записи.
5. Свои `private/config.php`, `assets/config.js`, QR-код и общие стили оставьте на месте: архив обновления их не содержит.
6. Обновите `/account.html` через Ctrl+F5 и войдите как администратор.

## 2. Добавить подписку в админке

Откройте **«Админка → Серверы»**:

1. Вставьте одну HTTPS-ссылку в **«Подписка для проверки»**.
2. Включите **«Показывать доступность серверов на сайте»** и сохраните.
3. Нажмите **«Создать токен для Ubuntu»** и скопируйте токен. Он показывается один раз; на сервере сайта хранится только его хеш. Если потеряли токен, создайте новый и повторно запустите настройку службы.
4. Полный URL подписки после сохранения не возвращается в браузер. Пустое поле при следующем сохранении сохраняет прежнюю ссылку.

Подписка должна возвращать обычный список `vless://`, `vmess://`, `trojan://`, `ss://` или такой же список в Base64 — стандартный формат подписок 3x-ui/V2RayN. До 100 записей, до 2 МБ; повторы удаляются автоматически. Источник обновляется примерно раз в 5 минут, проверка соединений планируется раз в минуту. При большом количестве медленных узлов полный цикл может занимать больше времени; результаты приходят по мере проверки.

Поддерживаются обычные варианты TCP, WebSocket, gRPC, HTTPUpgrade, XHTTP, TLS и Reality при поддержке их вашей версией Xray. Дополнительные XHTTP `extra`, плагины Shadowsocks, небезопасная проверка TLS, YAML/Clash, JSON-конфигурации и другие протоколы в эту версию не включены. Неподдерживаемые/неподходящие конфигурации показываются как **«Требуется настройка»**, а не как отключённые серверы. Если ссылка отдаёт HTML-страницу, авторизацию панели или иной формат, админка сообщит об ошибке источника.

Каждая запись проверяется отдельным клиентом Xray с единственным выходом — через конкретный узел. Переключение на другой VPN-узел не используется. Проверка запрашивает контрольный HTTPS-адрес и принимает только пустой ответ 204; предусмотрен второй контрольный адрес. Измеряется полное время HTTPS-запроса через VPN с Ubuntu-сервера. У посетителя задержка может отличаться. На странице отображается только число с единицей, например **258 мс**, без подписи.

Если в подписке указаны только входы вашего сервера, скрытые за ним внутренние выходы автоматически обнаружить нельзя. Для их отдельной проверки в подписке нужны отдельные подключения, направленные именно на соответствующие выходы.

## 3. Установить службу на Ubuntu

Подключитесь по SSH к вашему Ubuntu-серверу. Команды выполняются построчно:

```bash
sudo apt update
sudo apt install -y python3 curl unzip ca-certificates
mkdir -p "$HOME/moskom-monitor-v8"
cd "$HOME/moskom-monitor-v8"
curl -fL https://github.com/stisvladnext3-creator/moskompremont/raw/refs/heads/main/downloads/moskompremont-monitor-ubuntu-v8.zip -o agent.zip
unzip -o agent.zip
sudo bash install.sh
```

Установщик спросит:

- **Адрес API сайта** — нажмите Enter, чтобы оставить `https://moskompremont.ru/api/monitor-agent.php`.
- **Токен** — вставьте токен из настоящей админки сайта. Ввод скрыт: символы при вставке не отображаются, это нормально.

Установщик найдёт Xray в `/usr/local/x-ui/bin/xray-linux-amd64`, `xray-linux-arm64`, `/usr/local/bin/xray` или `/usr/bin/xray`. Если путь другой, укажите его явно:

```bash
sudo XRAY_BIN=/полный/путь/к/xray bash install.sh
```

Служба запускается от отдельного пользователя `mkr-monitor`. Настройки находятся в `/etc/moskom-monitor/config.json`, код и копия Xray — в `/opt/moskom-monitor`. Рабочие порты SOCKS открываются только на 127.0.0.1 и удаляются после каждой проверки.

Проверка службы и журнала:

```bash
sudo systemctl status moskom-monitor --no-pager
sudo journalctl -u moskom-monitor -n 30 --no-pager
```

При нормальной работе появятся строки «Проверено узлов: …; доступны: …». Через 1–2 минуты откройте `https://moskompremont.ru/internet.html#servers-section`. Сайт показывает названия, состояния и результаты проверки, не выдавая ссылку-подписку, UUID, пароли и конфигурации.

Состояния: «Доступен», «Недоступен», «Нет свежих данных», «Требуется настройка». Результат старше 3 минут перестаёт отображаться как доступный; последнее число задержки скрывается. Время последней проверки остаётся видно.

### Отдельная проверка вашего основного сервера снаружи

В «Серверы» раскройте **«Отдельная проверка основного сервера»** и укажите публичный домен/IP и **порт VPN-подключения**. Это не обязательно порт веб-панели 3x-ui. Сохраните настройки.

Проверка TCP выполняется с хостинга сайта и кэшируется на минуту. Она продолжает работать, даже когда Ubuntu-сервер и служба мониторинга остановлены. При открытом порте основной сервер отображается доступным; работу VPN через каждый маршрут отдельно проверяет служба. Если хостинг запрещает исходящие TCP-подключения или DNS, проверку нужно разрешить у провайдера хостинга. Приватные и служебные IP не проверяются. Дополнительный cron не обязателен; при желании `private/check-main-server.php` можно запускать раз в минуту, чтобы заранее обновлять кэш.

## 4. Письма, которые остаются в очереди

Служба Ubuntu отдельно от проверок VPN **раз в минуту** обращается к сайту для обработки одного письма. Отправка выполняется самим PHP-хостингом по вашим SMTP-настройкам; Ubuntu не получает пароль почты и содержимое писем. Обработка работает и при выключенном отображении серверов. Альтернатива — имеющийся cron `private/send-mail.php` на PHP-хостинге. Одновременный запуск защищён блокировкой записей очереди.

Откройте **«Админка → Почта»**. Теперь видно:

- какие настройки не заполнены;
- когда очередь обрабатывалась в последний раз;
- последние 20 писем, их статусы и число попыток;
- безопасное описание причины ошибки без паролей и SMTP-переписки.

Для Яндекс Почты проверьте существующий **private/config.php**, раздел `mail`:

```php
'mail' => [
    'enabled' => true,
    'transport' => 'smtp',
    'from' => 'sania.iwannikow@yandex.ru',
    'from_name' => 'МосКомпРемонт',
    'smtp_host' => 'smtp.yandex.ru',
    'smtp_port' => 465,
    'smtp_encryption' => 'ssl',
    'smtp_auth' => true,
    'smtp_user' => 'sania.iwannikow@yandex.ru',
    'smtp_password' => 'ВСТАВЬТЕ_ПАРОЛЬ_ПРИЛОЖЕНИЯ',
],
```

Это часть массива `return [...]`, не отдельный второй конфиг. Если блок `mail` уже существует, исправьте его, не добавляя дубликат. Используется пароль приложения Яндекса для почтового клиента, созданный в Яндекс ID → Безопасность → Пароли приложений; обычный пароль учётной записи может не подойти. Значение-пример замените целиком на действующий пароль. PHP должен поддерживать OpenSSL, а хостинг — исходящие соединения на smtp.yandex.ru:465.

Значения ошибок:

- `SMTP_AUTH` — сервер отклонил авторизацию: логин/пароль приложения или доступ почтового клиента.
- `SMTP_CONNECT` — недоступен SMTP-адрес/порт, соединение блокирует хостинг или есть сетевая ошибка.
- `SMTP_TLS` — ошибка защищённого соединения: порт, шифрование или сертификаты PHP.
- `SMTP_ADDRESS` — отклонён адрес отправителя/получателя; отправитель Яндекса обычно совпадает с логином.
- `SMTP_SEND` — письмо отклонено при отправке, проверьте ограничения почты.

После исправления нажмите **«Повторить отправку очереди»**, затем **«Отправить тестовое письмо»**. Тестовое письмо сначала попадает в очередь; служба подхватит его на следующем цикле. Статус «Принято почтовым сервером» означает принятие SMTP-сервером, а попадание именно во «Входящие» зависит от почты; проверьте также «Спам».

## Изменение токена, обновление и остановка

Новый токен отменяет прежний. Для замены заново выполните `sudo bash install.sh` в папке установщика; прежний адрес API можно оставить нажатием Enter. Повторная установка обновит код, копию Xray и перезапустит службу, сохранив адрес при пустом вводе. Обновлять службу после изменения только URL подписки не нужно.

Остановить фоновые проверки и обработку почты:

```bash
sudo systemctl disable --now moskom-monitor
```

## Проверено при подготовке

На изолированных тестовых данных проверены: настоящий HTTPS-источник и передача результатов, отдельное Xray/VLESS-подключение к контрольной HTTPS-странице, отличие работающего/отключённого/неподдерживаемого узла, отсутствие секретов в публичном JSON, смена токена и источника, устаревание результатов, получение писем тестовым SMTP-сервером, ошибка авторизации и повторная отправка. Реальная доставка на ваш Яндекс проверяется после установки с вашим действующим SMTP-паролем.
